# 原始像素布局开发计划

本文冻结无文件头 RGB、灰度、YUV 和 Bayer 输入的接口演进、支持子集、提交边界与验收顺序。A0 ABI4 描述和 A1 RGB / Gray 解码已经完成，YUV、Bayer 与应用入口仍按后续批次推进。文件扩展名、文件长度和分辨率都不能替代显式布局描述。

## 1. 总体边界

首版保留现有 ABI 3 的编码图片接口，并增加独立的原始像素请求接口。ABI 3 的 `lv_request_desc` 不加入布局字段，现有 JPEG、PNG、TIFF、RAW / DNG 等调用方继续使用原接口。原始像素接口采用独立的 ABI 4 描述版本，提交前检查精确 `struct_size` 和 `abi_version`。

原始像素请求仍只读取本地常规文件。请求携带数据文件路径、尺寸、方向、plane 描述、数值格式、颜色或 CFA 处理参数以及输出约束。Core 在提交时只校验并复制描述，不读取文件。worker 根据已复制的描述读取受检范围，并把首版结果转换为 RGBA8 后沿用现有事件和像素所有权契约。

首版不引入网络流、相机采集、用户 I/O 回调、DMA-BUF、任意内存借用、原生 YUV 纹理、HDR 输出、浮点输入、REGION、动态多帧和隐式 sidecar。A1 只接受显式 RGB24、BGR24、RGBA8、BGRA8 和 Gray8 描述，并统一输出 RGBA8。文件尾部允许存在未读取的字节，但任何 plane 的最后一个有效字节都必须在文件版本长度内。

## 2. 分批顺序

| 批次 | 范围 | 独立提交 | 必须通过的验收 |
| --- | --- | --- | --- |
| A0 | ABI 4 原始像素描述、复制、校验、请求身份和缓存键 | `b23459e raw-layout: add ABI4 request contract` | C / C++ 布局断言、初始化器、ABI 版本查询、旧 ABI 3 回归、非法描述同步拒绝，已通过 |
| A1 | RGB24、BGR24、RGBA8、BGRA8、Gray8 | `b798018`、`9167de4`、`acca64a`、`7e422de`、`ed70dc0`、`ae720e2`、`72727e3`、`bfa718d` | 真实 golden、stride / offset / 行方向、奇数尺寸、尾部字节、截断、预算、取消、源变更、FIT / NATIVE，已通过 |
| A2 | I420、YV12、NV12、NV21 的 8-bit YUV420 | `77b9ad8`、`9823d31`、`09454eb` | plane 边界、UV / VU 顺序、偶数尺寸、BT.601 limited / full、中心色度采样、截断、矩阵错误、FIT / NATIVE，已通过 |
| A3 | RGGB、BGGR、GRBG、GBRG 的 8-bit Bayer | `25c8c97`、`8dd7d0a`、`459feaf` | 四种 CFA 相位、黑白电平、固定白平衡、双线性去马赛克、边界 halo、四相位 golden、截断、预算、FIT / NATIVE，已通过 |
| A4 | 完整 16-bit Bayer 容器、little-endian / big-endian | `raw-layout: add 16-bit Bayer layouts` | 16-bit 字节序、黑白电平、白平衡、overflow、golden 和预算验收 |
| A5 | 应用显式参数入口 | `raw-layout: integrate explicit parameter entry` | CLI / 文件入口、参数复用、错误提示、目录过滤不猜布局、应用 smoke 和状态栏验收 |
| A6 | 性能与发行审查 | `raw-layout: review performance and packaging` | 真实高熵样本、冷 / 热加载、CPU 预算、安装 notices、Linux / Windows 配置检查和完整 CTest |

P010、P016、10 位以上 packed YUV、奇数色度尺寸、YUV444、YUV422、Bayer MIPI / V4L2 packed、REGION、随机访问、多帧和原生 GPU 多平面另立计划。它们不能因为 A1 到 A4 通过而自动标记为支持。

## 2.1 A2 细化计划

- 输入只支持 8-bit I420、YV12、NV12 和 NV21，宽高必须为正偶数，所有 plane 都显式给出 offset、stride、row_bytes 和 height。
- 颜色转换只支持 BT.601、full / limited range 和 center chroma siting。未知矩阵、BT.709 / BT.2020、cosited siting、P010 及其他高位深变体返回 `LV_ERROR_FORMAT_UNSUPPORTED`。
- I420 / YV12 使用独立 U、V plane，NV12 / NV21 使用交错 UV / VU plane。每个 plane 的最后有效字节都在打开文件的版本长度内，读取使用受检 64 位范围。
- Core 继续只接受 ABI4 显式请求，支持 FIT / NATIVE 和 TOP_DOWN / BOTTOM_UP，结果统一为 RGBA8。A2 不接入目录后缀、应用参数入口或 REGION。
- 提交顺序为 YUV 解码器、YUV golden 与边界测试、review 修正、Core 全量验收和兼容表更新，每批保留独立 Git 提交。

## 2.2 A3 细化计划

- 输入只支持 8-bit Bayer 单 plane，CFA 为 RGGB、BGGR、GRBG 或 GBRG，宽高为正值，支持显式 CFA 原点、TOP_DOWN / BOTTOM_UP、offset、stride、row_bytes 和 FIT / NATIVE。
- 处理只支持固定黑白电平、Q16 白平衡增益和双线性去马赛克。输入样本先按 black / white level 归一化，再按对应颜色增益处理，输出统一为 RGBA8。
- Bayer 边界使用确定的边缘采样策略，四种 CFA 和四种相位都必须有 golden 覆盖。非法 CFA、白电平不大于黑电平、增益为零和截断分别覆盖错误分类。
- A3 暂不实现 16-bit Bayer、MIPI / V4L2 packed、自动曝光、自动白平衡、HDR、REGION、随机访问和应用目录入口。
- 提交顺序为 Bayer 解码器、四种 CFA 与边界测试、review 修正、Core 全量验收和兼容表更新，每批保留独立 Git 提交。

## 2.3 A4 细化计划

- 输入支持与 A3 相同的四种 CFA，但样本为完整 16-bit Bayer 容器。`LV_RAW_BYTE_LITTLE` 和 `LV_RAW_BYTE_BIG` 明确指定字节序，`LV_RAW_BYTE_NATIVE` 按主机字节序读取。
- 黑白电平、Q16 白平衡和双线性去马赛克沿用 A3，16-bit 样本在同一线性处理中量化到 RGBA8。ABI4 当前没有 packed 有效位或位对齐字段，因此不猜测 10 / 12 / 14-bit 有效位。
- 覆盖四种 CFA、两种显式字节序、offset / stride、TOP_DOWN / BOTTOM_UP、FIT / NATIVE、截断、溢出和预算。MIPI / V4L2 packed、有效位左 / 右对齐、HDR 和 REGION 保持未支持。
- 提交顺序为 16-bit 解码器、字节序与 golden 测试、review 修正、Core 全量验收和兼容表更新，每批保留独立 Git 提交。

## 3. ABI 4 描述要求

原始像素 ABI 4 至少包含以下独立描述。布局、处理和输出不能编码进文件扩展名或未核验的短字符串。

| 描述 | 必须表达的字段 |
| --- | --- |
| 输入 | 本地路径、源版本锚点、有效宽高、存储行方向、显示方向 |
| Plane | 数量、相对偏移、正 stride、有效行字节数、每 plane 的高度和采样关系 |
| 数值 | layout 枚举、通道顺序、alpha 语义、容器位宽、有效位宽、对齐方式、字节序 |
| 颜色 | RGB / 灰度的颜色语义；YUV 的 matrix、range、chroma siting、primaries、transfer |
| Bayer | CFA pattern、原点、black level、white level、白平衡增益、处理质量 |
| 输出 | 允许的像素格式、精度、颜色、alpha、是否允许 CPU 转换回 RGBA8 |
| 身份 | 布局、处理、输出、target 和源版本全部进入内容缓存 key |

提交只复制有界描述和路径。首轮 plane 数不超过 4，描述数组和元数据有独立字节上限。所有整数乘法、加法、`offset + (height - 1) * stride + row_bytes` 都使用受检的 64 位运算。plane 重叠、非法 stride、超出文件长度、宽高为零和不支持的枚举在提交时同步拒绝或在 worker 中分类为对应错误。

## 4. 输出与颜色策略

A1 到 A4 只产生 RGBA8。Core INFO 报告实际输出和颜色语义，不能把未校准数据写成完整 sRGB、HDR 或 ICC 结果。RGB 与灰度按描述执行通道扩展，YUV 使用描述中的 matrix、range 和中心色度采样，Bayer 使用一次固定的黑白电平、白平衡和去马赛克配置。每个请求的处理参数固定，不能按 tile 自动曝光或改变白平衡。

当前 renderer 只接收 RGBA8。原始输入的 RGB / YUV / Bayer 平面在 Core 或应用准备阶段转换为 RGBA8，转换成本计入 CPU 预算和测试日志。原生 YUV 纹理、多平面 SDL 资源和 shader 由后续渲染阶段单独验收。

## 5. 应用入口

A5 使用显式 CLI 参数入口承载首版原始像素描述。参数文件或命令行选项必须同时指定数据文件、layout、宽高、stride / offset 以及颜色或 CFA 处理。没有完整描述时返回可读错误，不按扩展名、文件长度或分辨率猜测。目录导航只枚举已有编码格式，裸像素文件通过显式入口打开，并在信息面板显示实际布局和处理假设。

## 6. 每批通用验收

A0、A1、A2 和 A3 已完成验收。当前 ABI4 raw-layout 能力包含 RGB / Gray、8-bit YUV420 和 8-bit Bayer 子集，16-bit Bayer、应用显式参数入口和发行审查仍未完成。

- 正常输入必须通过 Core 请求和应用入口，INFO 的源尺寸、canvas、format、颜色和输出身份一致。
- 合法但首版不支持的 layout、位宽、plane 数、颜色矩阵或 target 返回明确的 `LV_ERROR_FORMAT_UNSUPPORTED` 或 `LV_ERROR_TARGET_UNSUPPORTED`。
- 截断、偏移溢出、stride 不足、plane 重叠和非法尺寸分别覆盖错误测试，不依赖进程崩溃或第三方日志。
- 预算失败、取消、源版本变化和队列背压必须保持现有终结事件、所有权和资源账本契约。
- 内容缓存 key 必须区分布局、处理、输出和 target。相同文件使用不同参数不能重放错误像素。
- CTest、C / C++ ABI 合约、应用 targeted tests、离屏 smoke 和必要的性能基线在各批次提交前通过。
- 文档只写已经验收的 layout。未完成的 YUV、Bayer、HDR、REGION 和 GPU 能力继续保留在待办中。
