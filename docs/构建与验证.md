# 构建与验证

本文集中维护构建、工具链、验证与文档导航。用户操作见 [README](../README.zh-CN.md)，安装布局见[打包说明](../packaging/README.md)。

## 构建与运行

需要 CMake 3.30+、Ninja，以及满足项目特性检查的工具链：Linux 使用 C23 / C++23；MSVC 使用 C17 兼容实现 / C++23。先初始化固定依赖；CMake 只使用本地源码，不自动下载：

```bash
git submodule update --init --recursive
cmake --preset dev
cmake --build --preset dev
ctest --preset dev
./build/dev/app/liltview /path/to/image.png
```

`dev` 构建应用与单元测试，`app-release` 构建发布应用；`debug` / `release` 默认仅构建核心及相应检查，`compat20` 为显式 C++20 核心兼容配置。可选回归见下文；依赖版本与维护方式见[第三方说明](../third_party/README.md)。x86 建议安装 NASM 以启用 JPEG SIMD。

### Windows / MSVC + Ninja 预设

`msvc-dev` / `msvc-release` 使用 x64 MSVC (`cl.exe`) 和 Ninja，分别继承 `dev` / `app-release` 的构建选项，输出到 `build/msvc-dev` / `build/msvc-release`，不与原有工具链混用构建缓存。

命令行需先打开 **x64 Native Tools Command Prompt for VS** 或初始化 x64 Developer PowerShell，并确保 CMake 3.30+、Ninja 在 `PATH` 中。预设不会自行调用 `VsDevCmd.bat`；支持 CMake Presets 的 IDE 可使用预设中的 `external` 架构 / 工具集信息初始化 MSVC 环境。

```powershell
# 开发：Debug 应用 + 单元测试
cmake --preset msvc-dev
cmake --build --preset msvc-dev
ctest --preset msvc-dev

# 发布：Release 应用，不构建测试
cmake --preset msvc-release
cmake --build --preset msvc-release
```

VS 2022 / VS 2026 共用这两个预设，由当前 Developer Shell 或 IDE 选择工具链，不硬编码 VS 安装目录。更换 VS 工具链应使用独立构建目录，避免复用另一个编译器的缓存，例如：

```powershell
# 在对应 VS 的 x64 Developer Shell 中执行
cmake --preset msvc-dev -B build/msvc-dev-vs2022
cmake --build build/msvc-dev-vs2022
ctest --test-dir build/msvc-dev-vs2022 --output-on-failure
# VS 2026 可对应使用 build/msvc-dev-vs2026
```

Windows 应用通过 `app/resources/liltview.rc.in` 嵌入现有多尺寸 ICO 和文件 / 产品版本信息。CMake 配置时从 `project(VERSION)` 生成构建目录中的 `app/generated/liltview.rc`；更新版本号或 RC 模板后重新配置即可，无需维护第二份版本号。Windows Release 通过目标属性 `WIN32_EXECUTABLE` 构建为窗口程序，不弹控制台；Debug 保留控制台用于诊断。默认仅有控制台日志 sink，不创建日志文件，`log_level` 只控制过滤等级。

MSVC 的 Core 明确使用 `/std:c17`、`/experimental:c11atomics`，并只对项目自有 C 目标启用私有 C23 写法兼容头；CMake 实际编译 / 链接检查 C11 原子与线程支持，不把 MSVC 声明为完整 C23 编译器。其他工具链保留原 C23 检查；公共 C ABI 不变。Windows 文件适配使用 UTF-8 到 UTF-16 的内部转换和 Win32 文件版本信息，tile 缓存使用删除即回收的临时文件和独立偏移读取。

**当前边界：应用统一使用 SDL3 + SDL_Render，底层驱动由 SDL 选择，不直接依赖 OpenGL，完整桌面与大图实机验收仍待完成。** UTF-16 Core 路径输入仍返回 `LV_UNSUPPORTED`；Windows 调用方应传绝对 UTF-8 路径。两项依赖 POSIX 特有“目录符号链接后接 `..`”解析语义的回归在 Windows 上明确跳过，其余常规测试保持启用。

CLI11 解析命令行，iguana 读写 `settings.yaml`；可用 `--language zh-CN`、`--language en-US` 或 `--config-dir PATH`，完整参数见[配置说明](命令行与设置.md)。

Linux 使用静态 SDL3 和 codec，仍需 Fontconfig、SDL 所选驱动及窗口运行库；默认全局菜单另需 GIO / GLib 和 `wayland-scanner`。`-DLILTVIEW_ENABLE_GLOBAL_MENU=OFF` 可构建窗口内菜单版本。开发桌面注册：

```bash
python3 scripts/register_desktop.py
```

文件选择器通过 SDL 调用桌面 Portal，需要 `xdg-desktop-portal` 和提供 FileChooser 的桌面后端（KDE 为 `xdg-desktop-portal-kde`）；也可用 Zenity 作为备用后端。如果无法打开，查看日志中的具体 SDL 错误，并检查用户会话的 Portal 服务。KDE 可执行 `systemctl --user restart plasma-xdg-desktop-portal-kde.service xdg-desktop-portal.service` 后重启应用。

应用 ID 为 `io.github.hui_livio.LiltView`。安装 / pacman / paru 部署见[打包说明](../packaging/README.md)和[Arch 指南](../packaging/arch/README.md)。

## 测试与兼容验证

单元测试统一使用项目自有 Catch2 入口：仅将“所选测试全部跳过”的退出码转换为 0，便于 VS Code 等直接运行测试的插件处理；CTest 通过独立 stderr 标记继续显示 Skipped。真实断言失败、参数错误和未匹配到测试仍返回非零，不使用放宽空测试检测的选项。

可选桌面与大图回归默认关闭，显式开启后构建并执行：

```bash
cmake --preset dev -DLILTVIEW_BUILD_DESKTOP_TESTS=ON -DLILTVIEW_BUILD_LARGE_IMAGE_TESTS=ON
cmake --build --preset dev
ctest --preset dev -LE large
ctest --preset dev -L large
```

桌面集成依赖 Linux、全局菜单及可用的 offscreen SDL_Render 驱动（可指定 software）；大图测试会生成 16K/32K 输入并消耗较多时间/磁盘。C++20 应用可另建目录并显式开启应用与单元测试，不能将默认 `compat20` 等同于完整应用验收。

| 测试位置 | 主要覆盖 |
| --- | --- |
| `tests/contract/` | C23 / C++20 / C++23 调用、公共结构布局及初始化器 |
| `tests/core/` | 格式边界、预算、版本、取消、区域、动画与像素所有权 |
| `tests/app/` | 设置/CLI、菜单、Viewport/Playback、Viewer、TileReader，以及无需图形窗口的延迟提交纹理 / 导航焦点回归 |
| `tests/integration/` | 真实 SDL_Render 回读、stride / target 状态恢复、清晰度、相机推进、源文件删除后恢复与应用回归 |
| 大图可选测试 | 16K/32K、受限单纹理/GPU 预算与边界像素 |

测试定义以 [tests/CMakeLists.txt](../tests/CMakeLists.txt) 为准。正确性测试不代替真实驱动性能测量；性能采样条件与指标见 [测试计划](../benchmarks/README.md)。安装与 Arch 部署见 [打包说明](../packaging/README.md)。

## Dock 交互与隐藏窗口渲染回归

Dock 时序、按钮 active 状态、FIT / 100% 双击、加载门控、拖拽所有权、主题 / DPI / 信息面板 / 全屏布局及更多菜单吸附包含在默认应用单元测试中（`[dock]`）。

如本机具有可用的 SDL_Render，可额外启用隐藏窗口渲染回归（含软件驱动契约）；默认关闭，避免给无图形环境的普通单元测试增加依赖：

```powershell
# 在 MSVC x64 开发环境中运行
cmake --preset msvc-dev -DLILTVIEW_BUILD_UI_RENDER_TESTS=ON
cmake --build --preset msvc-dev --parallel
ctest --test-dir build/msvc-dev --output-on-failure
# 可选输出实际渲染 PPM 截图（不覆盖 assets 中的静态设计图）
.\build\msvc-dev\tests\liltview_dock_render.exe build/dock-ui-check/captures
```

`ui.dock_render` 使用生产 Shell / Viewer / SDL_Render renderer，比较深浅主题、窗口 / 全屏布局和信息面板组合中的 framebuffer：显示只改变 Dock 覆盖区，隐藏后像素与之前完全一致；另检查长按按钮不淡出、双击模式切换和更多弹窗。它不代替原生全屏切换、跨屏 DPI 等完整实机矩阵验收。
