# LiltView 产品与设计

更新：2026-11-09。以当前工作区源码静态核对为准；“已实现”表示存在可用代码与对应测试，不代表本次重新完成运行验收。
开发实现与模块边界见[架构文档](ARCHITECTURE.md)，实际格式子集见[格式兼容表](IMAGE_FORMATS.md)，后续细项见[开发计划](DEVELOPMENT_PLAN.md)。

## 1. 产品定位

面向本地图片浏览的轻量桌面应用，首发平台为 Arch Linux。优先满足快速打开、原始细节查看、普通动图播放和静态大图浏览。

| 场景 | 用户目标 | 当前覆盖 |
| --- | --- | --- |
| 日常看图 | 打开文件，适应窗口或全屏查看 | 已实现；支持同目录连续浏览 |
| 检查细节 | 放大文字、图表和像素，拖动检查边缘 | 已实现；100% 按物理像素对齐 |
| 查看大图 | 原图超出单纹理尺寸时仍能查看完整内容 | 已有原始行带、分块缓存和纹理恢复；性能仍需优化 |
| 查看动图 | 正确呈现透明、帧合成和循环 | 已支持普通尺寸 GIF 自动播放 |
| 检查原始数据 | 设置 RGB / YUV / Bayer 参数后预览 | 待实现 |

产品原则：图片占据主要空间；打开和加载在后台执行；明确显示等待与失败；在预算内保留原始细节；格式支持按具体子能力声明。
“轻量”同时考察发布包、应用安装体积和新增系统依赖，不以单个可执行文件大小评价。

当前范围包括本地静态图片、普通尺寸动画和静态超大图。图片编辑、图库数据库、标签管理、批量处理不纳入当前范围。
CAD、PSD / PSB、AI、CDR、Sketch 等专用设计源文件及超大动图不纳入规划。

## 2. 界面与信息布局

```text
系统顶栏菜单（桌面支持时）
┌─────────────────────────────────────────┐
│ 图标 / LiltView               最小化 最大化 关闭 │
│ 文件  视图  设置  帮助（系统菜单不可用时）       │
├─────────────────────────────────────────┤
│                                         │
│                  图片画布                │
│                                         │
├─────────────────────────────────────────┤
│ 状态 | 文件名  宽 × 高             当前语言 │
└─────────────────────────────────────────┘
```

- 当前界面没有常驻按钮工具栏、目录树或缩略图条；菜单与画布边缘悬浮切图按钮提供浏览操作，右侧图片信息面板可按需打开。
- 系统顶栏与窗口内菜单使用相同动作、可用状态和快捷键，系统菜单可用时不重复显示窗口菜单。
- 空状态显示应用图标、名称和打开 / 拖入提示；通过文件菜单或快捷键打开。
- 状态栏显示加载 / 恢复 / 失败状态、文件名、源尺寸、目录序号和当前语言；缩放比例与详细信息在可切换的右侧面板中显示。
- 默认自绘无边框圆角窗口；最小客户区为 640 × 480。标题栏与状态栏空白可拖窗，边角可调整大小，图片区域拖动用于平移。
- 最大化和全屏使用直角；全屏隐藏自绘标题栏与边框。可在外观菜单切换系统标题栏及关闭圆角。

布局依据：[窗口与画布](../app/ui/shell.cpp)、[菜单模型](../app/menu/menu_model.cpp)、[窗口装饰](../app/ui/window_chrome.cpp)。

## 3. 核心操作

| 操作 | 已实现行为 |
| --- | --- |
| 打开 | 文件菜单、`Ctrl+O`、命令行文件参数、拖入单个文件 |
| 相邻图片 | `←` / `→`、视图菜单或画布左右边缘悬浮按钮；首尾不循环，对应操作禁用 |
| 适应窗口 | 菜单或 `F`；画布尺寸改变时保持适应模式 |
| 100% | 菜单或 `Ctrl+1`；一个源像素对应一个物理 framebuffer 像素，可用性由实际原始像素决定 |
| 鼠标缩放 | 静态图围绕指针缩放；滚轮每步倍率为 1.25 / 0.8 |
| 键盘缩放 | `Ctrl+↑` / `Ctrl+↓`，以画布中心为锚点，可长按 |
| 平移 | 静态图左键拖动；`Shift+方向键` 每步移动图片内容 64 个逻辑像素，可长按 |
| 全屏 | `F11` 切换；`Esc` 退出全屏，也可关闭关于弹窗 |
| 图片信息 | `I` 或视图菜单切换；`Esc` 优先关闭信息面板，下一次才退出全屏 |
| 退出 | 窗口关闭、文件菜单、`Ctrl+Q` |

图片适应窗口且没有超出画布时不能继续平移；达到边界后停止。
没有可显示图片时禁用适应、100%、缩放和平移；无法提供原尺寸时单独禁用 100%。文本输入和弹窗优先处理按键。
目录在后台枚举，按文件名自然排序（2 在 10 前，ASCII 忽略大小写后以原始名称稳定决胜）。仅纳入当前支持格式后缀及显式打开的当前文件；空 / 单图目录、扫描中或目录错误时，相应菜单与悬浮按钮禁用。坏图或文件删除不阻止继续切换，显式重新打开会刷新列表。
悬浮按钮不占画布布局，按下后拖出也不会平移底图；文本输入、弹窗与原生文件选择优先。双击切换 FIT / 100% 仍待实现。

信息面板按实际可见图片显示完整路径、文件大小、格式、原始 / 方向变换后尺寸、解码画布、物理像素缩放率、方向和输出像素 / 颜色状态；GIF 另显示当前帧、已知帧数 / 时长 / 总轮数。未知字段明确标注，不伪装成完整 EXIF / ICC 支持。换图尚无新像素或加载失败保留旧图时，面板也保持旧图信息；窗口缩小可滚动，画布、边缘按钮和状态栏互不覆盖。

## 4. 加载与显示体验

| 状态 | 当前行为与产品要求 |
| --- | --- |
| 等待打开 | 显示目标文件名与加载状态；后台探测、解码，过期请求取消 |
| 原始内容到达 | 支持流式路径的静态图按已完成行带呈现；未完成内容仍明确处于加载中 |
| 加载完成 | 当前图形成不可变原始场景；缩放和平移复用已生成像素及 LOD |
| 冷缓存恢复 | 后台读取 / 解压；优先显示已有完整画面，并在高清覆盖充足时推进相机，目标就绪后准确到达 |
| 失败 | 显示不支持、损坏、I/O 或预算不足等错误；已有旧图时可保留旧图并继续操作 |
| 关闭 | 先隐藏窗口，再取消、等待后台工作并释放资源 |

静态图当前使用单次 NATIVE 原始分辨率请求，放大不重新解码源文件。小图直接驻留 GPU；大图使用临时压缩 tile / 预生成 LOD 与有界纹理缓存。
JPEG / PNG / 未压缩 BMP / TIFF 可逐原始行带发布；这不等于 progressive JPEG 扫描预览或 Adam7 逐 pass 细化。
当前 FIT 是原始场景的显示方式，不能把旧版“先 FIT 再随相机请求 REGION”的方案当作现状。

高清缓存不足时仍可能保持最近画面等待；首次 LOD / 压缩 / 缓存写入及单次 GL 调用还可能阻塞 UI。
已有后台解码与恢复能力不构成固定响应时间承诺。强缩小质量、真实照片冷缓存延迟和跨屏高 DPI 仍需专项验收。

## 5. 视觉、语言与设置

- 使用中性画布、深浅两套界面；主题默认跟随系统并响应变化，手动选择深色 / 浅色后优先使用个人设置。
- 中文 / 英文可运行时切换，支持跟随系统；随包字体为 HarmonyOS Sans SC Regular，附独立许可。字体损坏或缺失时回退系统字体；无法提供中文字体时使用英文。
- 彩色应用图标采用蓝紫渐变底、暖白画框、薄荷山形和暖色光点，小尺寸使用简化版本。资源见[图标目录](../assets/icons/)。
- 语言、主题、窗口尺寸、标题栏和圆角选项保存在 `settings.yaml`；日志等级从配置读取、重启生效。具体字段与优先级见[配置说明](CONFIGURATION.md)。
- 关于弹窗提供版本、许可证、字体署名、作者与项目入口。

## 6. 功能状态

状态口径：**已实现**为当前支持子集已接通；**部分实现**为基础能力存在但仍有明确缺口；**待实现**为规划项；**不纳入**为当前范围排除项。

| 能力 | 状态 | 产品边界 / 后续缺口 |
| --- | --- | --- |
| 文件打开、错误反馈、继续打开其他文件 | 已实现 | CLI、菜单、快捷键、拖放均已接入 |
| JPEG、PNG、BMP、静态 WebP、基础 SVG、TIFF 首页 | 已实现 | 按[兼容表](IMAGE_FORMATS.md)声明子集；基础 SVG 不等同完整浏览器 SVG |
| 普通 GIF 动画 | 已实现 | 自动顺序播放、透明 / disposal / 循环；最小化或隐藏时暂停调度 |
| 动画手动控制 | 待实现 | 无用户暂停 / 继续、逐帧、时间轴或 seek 入口 |
| 适应、原尺寸、缩放、平移、全屏 | 已实现 | 动画按 FIT 帧显示；原尺寸可用性取决于实际帧输出 |
| EXIF / 图像方向 | 部分实现 | JPEG 与 TIFF 已处理；PNG / WebP 等方向与其他元数据仍有缺口 |
| 静态超大图 | 部分实现 | 四类区域 codec 已有 NATIVE 行带、tile / LOD 和恢复；progressive / interlace 等仍受工作集限制 |
| 当前图片缓存 | 已实现 | app 临时磁盘缓存、后台 RAM LRU 和 GPU 恢复已接通；不是跨启动持久图库缓存 |
| core 内容缓存、目录相邻图片预读 | 部分实现 | Core 已有有界静态完整结果 LRU 与真实 PREFETCH；主程序邻居调度仍待接入，不含动画会话缓存 |
| 目录枚举、排序、上一张 / 下一张 | 已实现 | 后台扫描、自然排序、目录序号、菜单 / 裸左右键 / 边缘按钮；扫描失败明确提示，首尾禁用 |
| 图片信息面板与实时缩放率 | 已实现 | 右侧面板按可见场景提供真实元数据；状态栏仍保持文件 / 尺寸 / 目录序号 |
| 中英、主题、全局菜单、窗口外观持久化 | 已实现 | Linux 桌面适配；系统菜单不可用时回退窗口内菜单 |
| 高 DPI | 部分实现 | 已有缩放布局和物理像素对齐；跨屏、输入法等仍需人工验收 |
| 色彩管理 / HDR | 待实现 | 当前 RGBA8；PNG 16 位缩至 8 位，无完整 ICC / HDR 输出链路 |
| Arch 打包 | 已实现 | 已有构建、用户桌面注册及本地 pacman / paru 部署脚本 |
| Windows / Win32 + D3D11 | 待实现 | 保留公共 C API / renderer 边界，尚无 Windows 后端验收 |
| 自定义图像 shader、RGB / YUV 直接渲染 | 待实现 | 当前使用 ImGui OpenGL 后端与单平面 RGBA8；PBO 上传优化不代表这些能力已完成 |
| 更新检测 | 待实现 | 延期；当前没有对应网络模块 |
| 专用设计源文件、超大动图 | 不纳入 | 通用格式导出文件仍按兼容表处理 |

## 7. 待实现范围与建议顺序

以下为整理后的**建议优先级**，没有新增交付日期；已确认的格式范围继续保留。

| 建议顺序 | 工作项 | 完成条件 |
| --- | --- | --- |
| P0 | 大图响应与资源治理 | 首次缓存生成迁出 UI；补齐 app 内存 / 磁盘总账；修复强缩小混叠；提供真实图片分阶段冷 / 热性能数据 |
| 已完成 | 同目录浏览闭环 | 后台枚举、稳定自然排序、上一张 / 下一张、首尾状态、目录序号及边缘按钮；快速切图过滤旧结果 |
| P1 | 预读与复用 | 在明确预算下预读相邻图片；当前显示优先，缓存失效、文件修改、取消和退出可恢复 |
| P2 | 动画控制与交互扩展 | 信息面板已完成；后续 GIF 暂停与继续、双击操作分别验收 |
| P2 | 扩展格式与颜色链路 | 先确定依赖、兼容子集与 API，再按静态 / 动画 / 高位深 / 颜色能力分别接入 |
| P3 | 原始像素、专用图像 pass | 可编辑输入参数和可解释颜色；预算、格式协商、CPU / GPU 路径及像素正确性分别验收 |
| P3 | Windows 与更新检测 | 工具链、文件名、窗口、renderer、安装部署和退出生命周期独立验收 |

扩展格式全部待实现：AVIF、JPEG XL、HEIF / HEIC、APNG、动画 WebP、ICO / CUR、QOI、JPEG 2000、OpenEXR、相机 RAW / DNG，以及 TIFF 多页选择。
相机 RAW 要分别验收内嵌预览与完整显影；高位深读取、HDR 到 SDR 映射、原生 HDR 输出也分别验收。

原始 RGB / 灰度、YUV、Bayer 全部待实现。产品需提供独立打开与参数入口，支持宽高、具体布局、位深、stride / offset、方向与颜色解释，参数可查看、修改和复用。
缺失信息时使用明确展示的假设或拒绝输入，不按扩展名猜布局；单帧原始文件不自动作为动画。具体格式、颜色、打包与校验要求集中在[开发计划](DEVELOPMENT_PLAN.md)。

## 8. 验收与文档维护

- 功能验收覆盖打开、失败恢复、取消、快速换图、关闭、资源释放及设置重启恢复；测试存在与实机验收分开记录。
- 画质验收覆盖 100% / 非整数缩放、透明边缘、EXIF 1..8、HiDPI、非均匀大图；缓存恢复不能露空白块或冒充原始细节。
- 每个新格式明确静态 / 动画、透明、位深、方向、颜色与区域能力；提供合法、损坏、截断、预算不足样本后再更新兼容表。
- 性能记录需注明构建、硬件 / 驱动、窗口 / DPI、输入版本、冷 / 热缓存，分别测首个原始内容、完整就绪、交互延迟与资源峰值；本文件不复用旧测试次数或旧耗时作为本次结论。
- 本文维护产品范围与交互状态；模块、线程、预算和开发待办由[架构文档](ARCHITECTURE.md)维护，格式细节由[兼容表](IMAGE_FORMATS.md)维护。
