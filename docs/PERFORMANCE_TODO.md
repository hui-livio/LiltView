- [ ] 分阶段计时：文件读取、解码、重采样、事件等待、纹理创建 / 上传、绘制提交与呈现；记录首个有效画面、操作到清晰细节的端到端耗时，以及交互帧耗时的 P50 / P95。区分等待细节与 UI 线程卡顿。
- [ ] 排查 JPEG / PNG 在视口变化时重复扫描的成本，评估有界解码会话、缩放层级或图块结果缓存；不得以完整超大 RGBA 常驻来换取响应。
- [ ] 排查相邻 REGION 的重复解码和重复上传，评估复用已覆盖图块、仅请求新增覆盖，以及连续操作期间的请求合并和过期任务取消。
- [ ] 排查每次候选图层重建纹理的成本，评估有界纹理复用；始终计入预览、当前、候选与可复用资源的 GPU 预算。
- [ ] 评估首批有效区域更早呈现、可见区域优先级和预取余量。当前完成整个请求后切换细节的策略可能影响体感，需与版本核验、取消及错误恢复一起设计。
- [ ] 根据测量结果优化行采样、TIFF 局部访问和 UI 每帧上传额度，验证单次上传或事件消费是否阻塞交互；不凭总测试耗时推断具体瓶颈。

## 已确定的方向：按视口懒加载

2026-11-08 用户明确：放大采用 lazy load，只按需处理当前可视区域；画面外的细节暂不计算，拖动进入视口后再计算。此处记录目标，尚未实现新增优化。

- [ ] 将视口映射到当前缩放级别的图块集合，只解码、生成和上传可见范围内缺失的细节；不因放大而计算整张源图的高分辨率输出。
- [ ] 拖动后计算新旧可见图块集合的差集：重叠区域复用，只为新进入视口且尚未缓存的图块提交任务。已缓存且源版本、分辨率匹配的图块直接复用。
- [ ] 离开视口的未完成任务取消或降低优先级；已完成图块仅按有界缓存策略保留。连续拖动以最新视口为准，避免过期计算阻塞当前可见内容。
- [ ] 当前可见内容优先，默认不主动生成视口外细节；图块对齐和滤波所需的最小边界属于实现余量，额外预取须单独测量后再决定。等待新细节时可继续显示已有预览和有效图块。

现有实现已按 REGION 请求局部输出，但仍有区域余量、候选整层替换及重复处理重叠区域等优化空间，不能将其等同于上述按缺失图块懒加载已经完成。JPEG / PNG 等顺序编码可能仍需读取或扫描视口外的压缩数据；该格式限制不应变成生成、保存或上传整张高分辨率图像的理由。

## 优化必须保留的约束

- 最终解码输出到事件 / UI 通过原指针、共享视图和引用计数交接，不增加 CPU 像素深拷贝。
- 已发布或被 retain 的像素始终不可变，最后引用释放后才允许复用；保持取消、源版本核验及 shutdown 的生命周期契约。
- 不以拉伸低分辨率预览代替最终清晰细节；保留原尺寸像素和最近邻放大的正确性检查。
- CPU / GPU 缓存、解码会话和复用资源必须有界，不能提高内存上限或引入无界预读来掩盖性能问题。
- 每项优化分别记录前后测量及正确性回归，不把现有 16K / 32K 功能验收当作与 VS Code 的性能对比结果。
