## 1. 总体结论与状态口径

**基础图片浏览闭环已实现：7 类格式的受限子集、同目录连续浏览、静态图片缩放平移、普通 GIF 自动播放、状态与失败反馈均已接通。大图性能、扩展格式、颜色链路及 Windows 完整交付仍未收尾。**

| 状态 | 含义 |
| --- | --- |
| 已实现 | 当前声明的支持子集已有可用实现，不代表该格式的所有变体都兼容 |
| 部分实现 | 基础链路已接通，但仍有明确功能、性能或验收缺口 |
| 待实现 | 已列入开发范围，当前尚无可用实现；不等于已经锁定依赖或交付日期 |
| 不支持、暂不排期 | 当前没有支持方案，也没有实施日期；满足重新立项条件后才评估 |
| 不纳入当前规划 | 明确排除在当前产品范围外，不作为待开发承诺 |

未出现在支持表中的格式不能默认视为已支持；未列入计划也不自动意味着永久拒绝支持。

## 2. 图片格式

### 2.1 已支持：7 类，均有兼容边界

| 格式 | 已实现能力 | 主要未支持子能力 / 限制 |
| --- | --- | --- |
| JPEG（`.jpg` / `.jpeg`） | 8 位 RGB / 灰度，baseline / progressive 最终结果，EXIF 方向 1..8 | CMYK / YCCK、12 位、progressive 扫描预览、ICC 转换未实现 |
| PNG（`.png`） | RGB / RGBA / 灰度 / 索引色、透明、合法位深组合、Adam7 | 16 位输入转为 8 位输出；APNG 明确拒绝；不应用 ICC、gamma、PNG EXIF |
| WebP（`.webp`） | 静态有损 / 无损及 alpha | 动画 WebP 明确拒绝；不应用 ICC / EXIF 方向 |
| BMP（`.bmp`） | 1 / 4 / 8 位调色板，16 / 24 / 32 位真彩，bitfields，RLE4 / RLE8，上下行序 | 不支持内嵌 JPEG / PNG、OS/2 扩展压缩；RLE 不支持 top-down / REGION；alpha 依赖显式掩码 |
| SVG（`.svg`） | 基础静态路径、几何、渐变、变换、透明度及 viewBox | 复杂 SVG 不支持；应用按自然尺寸栅格化后复用像素，不会随放大重新矢量栅格化 |
| GIF（`.gif`） | GIF87a / GIF89a，普通尺寸自动播放，透明、交错、disposal、源帧时长与循环 | 无手动播放控制 / seek，不支持超大动图；UserInputFlag 拒绝；Core 静态入口仅取首帧 |
| TIFF（`.tif` / `.tiff`） | Classic / BigTIFF 首页，大小端、strip / tile、常见压缩、方向与显式 alpha | 无多页切换、浮点 / CMYK；不支持部分位深 / 调色板组合；显示输出仍为 RGBA8 |

支持是按文件实际编码特性判断，不是“扩展名匹配即成功”。显式打开时解码器按内容探测；同目录导航按当前登记的支持后缀筛选，二者不能混为一谈。

源码核对入口：[内容探测](../core/src/codecs/image.c)、[格式能力查询](../core/src/api/engine.c)、[目录后缀登记](../app/viewer/viewer.cpp)、[格式回归用例](../tests/core/format_tests.cpp)、[GIF / TIFF 用例](../tests/core/gif_tiff_tests.cpp)。完整子集与资源限制见[格式兼容表](IMAGE_FORMATS.md)。

### 2.2 当前未支持，但已列入待实现范围

| 格式 / 能力 | 后续范围与验收边界 |
| --- | --- |
| AVIF | 主图、有损 / 无损、透明、高位深；动画另项验收 |
| JPEG XL | 有损 / 无损、透明、高位深、渐进及 JPEG 无损重压缩文件读取；动画另项 |
| HEIF / HEIC | 明确容器与 codec 子集、主图、方向 / 裁切、透明、高位深；集合 / 序列另项 |
| APNG | 正确处理 frame 0、帧合成、disposal、时长和循环；只显示默认静态图不算完成 |
| 动画 WebP | 完整画布与透明合成、帧时长及循环 |
| ICO / CUR | PNG / DIB 条目、多尺寸选择、alpha / mask、CUR 热点 |
| QOI | RGB / RGBA 无损读取 |
| JPEG 2000 | 明确 JP2 / J2K 子集、位深、颜色及区域 / 分辨率访问成本 |
| OpenEXR | 明确 part / 通道、半浮点 / 浮点映射、window / origin、压缩与 scanline / tile 子集；deep 等另项 |
| 相机 RAW / DNG | 明确相机 / 编码子集；内嵌预览与完整显影分别验收，不承诺所有机型 |
| TIFF 多页 | 首页以外的页面枚举 / 选择；不自动当作动画 |
| 裸 RGB / 灰度 / YUV / Bayer | 独立打开与参数编辑入口；宽高、布局、位深、stride / offset、字节序、方向和颜色解释均需明确 |

以上尚未锁定新增 codec 依赖或交付时间。JPEG CMYK / 12 位、TIFF 浮点等现有格式的未支持变体，也不能仅凭“该格式已支持”推断可用，或推断已有单独实施承诺。

相机 RAW / DNG 与无文件头的裸像素是两类输入；`.raw` / `.yuv` 后缀或文件长度不足以唯一确定像素布局。详细要求见[开发计划](DEVELOPMENT_PLAN.md)。

### 2.3 暂不支持且不安排实施日期

**复杂 SVG：当前只承诺基础静态 profile，不提供浏览器级兼容。**

- 文字 / 字体、CSS stylesheet / class、clipPath、mask、filter、use / symbol、image（含 data URI）不在支持范围内。
- 不支持脚本、SVG 动画、foreignObject / HTML、DTD / 实体及外部资源，不执行脚本或访问引用的外部文件 / 网络。
- 当前不更换后端、不新增矢量渲染通道、不安排实现日期；不是普通扩展格式队列中的已承诺事项。
- 仅在目标样本、轻量 C/C++ 后端、资源与安全边界、跨平台构建及像素正确性等重新立项条件满足后再评估；不表述为永远不支持。

参考：[SVG profile](IMAGE_FORMATS.md#4-svg-静态-profile)、[复杂 SVG 技术决策](DEVELOPMENT_PLAN.md#8-复杂-svg-范围与技术决策)。

### 2.4 不纳入当前规划

| 范围 | 结论 |
| --- | --- |
| CAD、PSD / PSB、AI、CDR、Sketch 等专用设计源文件 | 不纳入；从这些工具导出的通用图片仍按实际格式兼容表处理 |
| 超大动图 | 不纳入；普通尺寸 GIF 与静态超大图是当前两个独立支持方向 |
| 图片编辑、图库数据库、标签管理、批量处理 | 不纳入当前产品范围，不作为看图功能的后续承诺 |

范围依据：[产品定位](PRODUCT_DESIGN.md#1-产品定位)、[扩展格式范围](DEVELOPMENT_PLAN.md#2-文件格式范围全部待实现)。

## 5. 待开发功能与建议顺序

下表沿用现有开发计划的建议优先级，不新增日期、依赖选型或范围承诺。

| 建议优先级 | 工作 | 完成条件 / 说明 |
| --- | --- | --- |
| P0 | 大图首次加载后台化 | 首次 LOD、压缩和缓存写入迁出 UI；分别测首行带、全图完成与 100% 恢复，不把后台恢复等同于首次全链路后台化 |
| P0 | 资源总账与失败恢复 | 统一 app 索引、描述符、LOD、暂存、旧 / 新场景与本地缓存预算；补磁盘不足、I/O 失败与恢复 |
| P0 | 缩小画质与冷 LOD | 改善强缩小混叠、冷层级批量驻留与预测预热，建立可复现的真实图冷 / 热基线 |
| P2 | 动画控制与交互 | GIF 暂停 / 继续、双击切换 FIT / 100%；当前没有逐帧、时间轴或 seek 入口，扩展时需单独定义与验收 |
| P2 | 扩展格式 | 接入第 2.2 节各项，逐格式验收静态 / 动画、透明、位深、方向、资源与取消，不因上游库支持就宣布应用支持 |
| P2 | 颜色与高精度链路 | 完整 ICC、保留高位深、HDR 到 SDR 映射、原生 HDR 输出分别验收；当前统一显示输出为 RGBA8 |
| P3 | 原始像素入口 | RGB / 灰度 / YUV / Bayer 的可编辑、可复用参数，明确 packing、stride / offset、颜色及 Bayer 标定 / 去马赛克 |
| P3 | 专用图像渲染路径 | 独立 image pass、自定义图像 shader、RGB / YUV 原生纹理与 GPU 多平面；现有 PBO 不等于这些能力已完成 |

建议先收尾现有大图性能与资源治理，再推进交互、扩展格式和颜色链路；不要通过增加格式数量掩盖现有浏览路径的响应与画质缺口。详细接口及验收条件见[开发计划](DEVELOPMENT_PLAN.md)。
