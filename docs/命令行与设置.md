# 命令行与 YAML 设置

命令行解析使用 CLI11 v2.5.0；配置序列化和反序列化使用固定提交的 iguana YAML reader / writer。二者为直接保存在 `third_party/` 的纯头文件依赖，不进入 C core 或 renderer。

## 命令行

```bash
liltview [options] [image]
liltview --language zh-CN --config-dir /tmp/liltview-settings photo.jpg
liltview --help
```

| 参数 | 含义 |
| --- | --- |
| `--language system\|en-US\|zh-CN` | 覆盖保存的语言，正常退出后随设置保存 |
| `--config-dir PATH` | 将 settings.yaml 放在指定目录 |
| `--smoke-test` | 隐藏窗口执行冒烟流程并退出，不保存设置 |
| `--screenshot PATH` | 需同时提供 --smoke-test，输出 PPM 截图；圆角／透明窗口另输出同名 `-alpha.pgm` 透明度诊断图 |
| `--help` / `-h`、`--version` | 显示 CLI11 帮助 / 应用版本，退出前不初始化窗口 |
| 一个位置参数 | 打开的图片路径；以 `-` 开头的文件名用 `--` 分隔 |

帮助、选项值校验、重复 / 多余参数和依赖关系由 CLI11 处理。错误返回非零 CLI11 退出码，不依赖固定数值。未提供 --language 时使用配置偏好；没有配置时跟随系统。仅接收一个图片位置参数；打开后由应用后台枚举同目录供导航，Core 仍处理独立文件。快捷键、悬浮按钮与信息面板见[产品设计](产品与设计.md)。

## settings.yaml

默认位置是 SDL 用户配置目录中的 `settings.yaml`；可用 --config-dir 隔离。只读取这个文件名，不读取、导入或迁移旧 INI；只存在旧 INI 时以默认值启动。

信息面板开关仅保留本次会话状态；内容缓存 / 邻居预读预算使用应用默认值，没有新增对应 CLI 或 YAML 字段。

```yaml
width: 1120
height: 760
maximized: false
theme: system
language: system
log_level: warn
system_titlebar: false
disable_rounding: false
```

- width 为 640..8192，height 为 480..8192；越界字段回退各自默认值。
- maximized 使用 true / false。
- system_titlebar 默认 false，使用自绘无边框标题栏；true 恢复系统标题栏和边框。在“设置 → 外观 → 启用系统标题栏”即时切换，退出保存。
- Windows 系统标题栏由 DWM 绘制，随应用最终解析的深浅主题同步（包括标题栏文字与右侧窗口按钮），而非固定跟随系统颜色；Windows 10 同步每窗口原生深色颜色策略，在主题切换、窗口显示或边框/区域重建后刷新非客户区与标题栏激活态绘制缓存，不改变真实焦点、位置和尺寸，不需要用户切换焦点或最大化/缩放窗口；切换回系统标题栏时移除自定义 Win32 窗口区域，不留下导致经典边框的矩形 HRGN。自绘圆角模式使用独立 Win32 区域；关闭圆角或最大化时移除该区域。不支持深色标题栏属性的系统保留原生默认颜色，不阻止启动。
- disable_rounding 默认 false，无边框窗口使用透明圆角；true 使用直角。在“设置 → 外观 → 关闭圆角”切换。原生标题栏下该项禁用但保留选择，最大化 / 全屏自动直角。
- theme 使用 system / dark / light，language 使用 system / en-US / zh-CN；不认识的值回退 system。
- log_level 使用 trace / debug / info / warn / error / critical / off；有效配置优先于构建默认值。Debug 开发构建默认 debug，Release / RelWithDebInfo / MinSizeRel 发布构建默认 warn；缺失或值无效时使用该构建默认值。上例显式选择 warn。
- 默认不输出日志文件，也不自动创建日志目录；目前仅使用 spdlog 控制台 sink，`log_level` 不会开启文件日志。Windows Release 是无控制台的窗口程序，Debug 保留控制台；需要控制台诊断时使用 Debug 构建。
- 设置读取完成后、创建工作线程前，将 log_level 应用到 spdlog。启动期间读取配置前先使用构建默认值；运行中不监控文件变化，修改后需重启。保存时记录实际使用的等级，因此已有有效配置在更换构建类型后仍然优先。
- 缺失字段保留默认值。支持单个普通 YAML 映射、注释、引号、UTF-8 BOM、CRLF 及可选的 --- / ... 文档标记；不接受多文档，配置不承诺任意 YAML 高级特性。
- 空文件使用默认值；文件超过 4096 字节、含 NUL、字段类型错误、未知键或语法错误时使用整份默认配置，不应用已解析的半份结果。
- 解析由 iguana 完成，应用只负责长度、字段范围与枚举映射，不保留手写 key=value parser。

固定的 iguana 快照对字符串字段类型和缩进校验较宽松，已保留一个有来源记录的最小补丁：拒绝把集合、别名及无效 plain scalar 当作字符串，拒绝映射键缩进不一致。补丁与校验信息保存在 third_party/iguana，应用只做单文档边界归一化，不再引入另一种配置解析器。

保存仍采用同目录临时文件：先序列化，再写入、刷新和关闭，成功后替换目标文件；检查失败时保留旧文件。现有普通文件权限与有效符号链接处理保留，拒绝目录和特殊设备；不承诺 fsync 级断电持久性。程序退出只保存当前字段，不保留手动注释和键顺序。

源代码入口：[`app/cli/options.cpp`](../app/cli/options.cpp)、[`app/settings/settings.cpp`](../app/settings/settings.cpp)、[`app/settings/store.cpp`](../app/settings/store.cpp)。

日志适配见 [`app/logging/configure.cpp`](../app/logging/configure.cpp)。--smoke-test 禁止 false / 0 等 flag override，防止它只作为依赖参数出现而实际未启用冒烟测试。

## 静态图片首次上传策略（仅配置）

在 `settings.yaml` 中设置，重启后生效，不提供 UI 菜单：

```yaml
static_upload_mode: pipeline # 默认；batch 为全部准备完成后集中上传
static_cache_compression: true # 默认；false 使用原始 RGBA 内存缓存
log_level: info             # 记录首次加载阶段时间线；Release 默认 warn 不输出 info
```

未知策略值回退 `pipeline`；旧配置缺少此项时保持默认。两种策略都在首屏完整后一次显示；`batch` 是加载对照模式，并不上传超大图片所有不可见原始细节，且最多使用 80 MiB 暂存。集中上传可能造成长帧，日常建议保留 `pipeline`。配置保存会保留此字段。

计时日志：`static_load_begin`、`static_load_decode`（debug）、`static_load_ready`、`static_load_present`；包括 generation、实际策略、首块 / COMPLETE / 准备完成、首次 / 最后上传、首屏就绪、提交与 present 返回时间，以及上传处理片段峰值和队列高水位。CPU 阶段为线程内墙钟耗时，Core elapsed 包含排队 / 背压，不冒充纯解码 CPU 时间；present 返回不等于屏幕实际扫描完成。

### 场景缓存压缩（仅配置）

`static_cache_compression` 为布尔值，缺省 `true`，不显示在菜单或设置 UI，保存时保留，修改后重启生效。

- `true`：需要 CPU 场景缓存时使用 LZ4 独立块和 XXH32 校验，恢复细节时按需解压。
- `false`：缓存原始 RGBA / LOD 内存块，恢复时增加引用，不压缩、不解压、不复制 payload。
- 两者均不创建 / 读写磁盘图块缓存；源文件读取、配置保存不在此约束内。操作系统分页也不受应用保证。
- 能完整驻留 GPU 的预算友好图片走直接上传，通常包括默认 128 MiB 图片预算下的 4K。该路径本来就不压缩，开关不强制改变路径。
- 大图原始缓存必须在缩放时保留；不能在首屏渲染后立即全部销毁。上传后的临时原始块在最后引用释放时回收。为避免长期 pin 住 Core 的有限 backing，原始缓存必要时做一次所有权复制，之后跨模块只传 C 内存块引用。
- 活动、待显示、退休场景合计最多 2 GiB 缓存分配容量加保守元数据；Core、GPU、队列、scratch 另计，不是进程 RSS 总上限。超限明确失败，不回退磁盘缓存。

开关对照方法：`benchmarks/cache_compression_compare.py`；记录完整首屏、压缩 / 解压、100% 恢复、稳定渲染与峰值 RSS，不把压缩阶段单独变快当作整体秒开。
